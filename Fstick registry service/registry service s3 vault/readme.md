# Архитектура хранения файлов (S3/MinIO)

Этот документ описывает структуру хранения артефактов плагинов (архивы кода, скриншоты) в объектном хранилище S3 (или совместимом MinIO), соглашения об именовании и механизмы безопасного доступа.

## 1. Общие принципы безопасности

*   **Приватный бакет:** Бакет S3/MinIO должен быть настроен как `PRIVATE`. Прямой публичный доступ к файлам запрещен.
*   **Presigned URLs:** Доступ к файлам осуществляется исключительно через временные подписанные URL (Presigned URLs), генерируемые бэкендом.
*   **Разделение ответственности:**
    *   **PostgreSQL:** Хранит метаданные (названия, описания, связи) и пути (keys) к файлам в S3.
    *   **S3/MinIO:** Хранит сами бинарные файлы (архивы `.zip`, изображения `.png/.jpg`).

## 2. Структура путей (Key Structure)

Все файлы хранятся в одном бакете (например, `f-stick-plugins`) со следующей иерархией:

```text
f-stick-plugins/
├── plugins/
│   └── {plugin_id}/              # UUID плагина (например, 550e8400-...)
│       ├── screenshots/          # Папка для скриншотов
│       │   ├── {uuid_v4}.png     # Уникальное имя файла
│       │   └── {uuid_v4}.jpg
│       └── versions/
│           └── {version_number}/ # Версия SemVer (например, 1.0.0)
│               ├── archive.zip   # Архив с исходным кодом
│               └── manifest.json # (Опционально) Метаданные версии
```

## 3. Соглашения об именовании (Naming Convention)
| Сущность | Формат | Примичание |
| :--- | :---: | ---: |
| Plugin | ID UUID v4 | Используется как корневая директория |
| Version | SemVer | Название папки внутри versions |
| Archive | archive.{ext} | Стандартное имя архива внутри папки версии |
| Screenshot | {UUID}.{ext} | UUID генерируется при загрузке. Расширение сохраняется оригинальное |


## 4.1 Загрузка файла (Upload)

Используется для загрузки новых версий или скриншотов:

1) Клиент запрашивает у API эндпоинт получения URL для загрузки.
2) Бэкенд генерирует Presigned PUT URL (срок жизни: 5–15 минут).
3) Клиент загружает файл напрямую в S3 по этой ссылке (метод PUT).
4) После успешной загрузки клиент отправляет бэкенду подтверждение и ключ файла (object_key).
5) Бэкенд сохраняет ключ в PostgreSQL.

## 4.2 Скачивание/Просмотр (Download)

Используется для получения архивов и отображения скриншотов:

1) Клиент запрашивает информацию о плагине/версии.
2) Бэкенд извлекает s3_key из PostgreSQL.
3) Бэкенд генерирует Presigned GET URL (срок жизни: 15–60 минут).
4) Бэкенд возвращает URL в JSON-ответе.
5) Клиент использует ссылку для скачивания или отображения (<img src="...">).

## 5 Жизненный цикл и очистка (Cleanup)
S3/MinIO не удаляет файлы автоматически при удалении записей из БД. Реализация очистки ложится на бэкенд.
